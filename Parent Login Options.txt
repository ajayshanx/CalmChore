When a child logs in, they should have the following menu options:

"Chores" tab:
There should be multiple sub tab within this tab.
These tabs could be "Active Chores", "Ongoing Chores", "Iactive Chores", "All Chores", "Chore Ideas"
- Active Chores would list all created chores that have a current or future schedule, whether assigned, accepted or unassigned to one or more of the parents's children
- Ongoing Chores would list all created chores accepted or assigned by one or more children of the logged-in parent
- InactiveChores should list all created chores that have a status of 'Inactive'
- All Chores should list all created chores by this or other parents of this account
- Chore Ideas should list all chores created by all creators using the app
Note that given that there could be hundreds of chores, we need a alphabetized grouping, where clicking on A lists all chores starting with A and so on.
If the same alphabet has more than say 10-20 tasks (as fits a mobile screen), then we must implement pagination.
There should also be a search textbox that searches across all alphabets based on chore name.

Chores that list across the Active / Ongoing tabs should have the following info about each chore:
- Chore Name
- Schedule (Date / Time)
- Deadline
- Points
- Assigned To
- Accepted By
- Status
Note: that information that shows should be related to the current instance of the chore (if not verified complete or partially complete) OR the next instance of the chore.

The All Chores / Inactive Chores tab should have the following info about the chores: (basic chore info and not instance info shows)
- Chore Name
- Info preview
- Current / Next Instance (Date / Time)
- Previous Instance (Date / Time)

The Chore Ideas tab should show just the Chore Name and a preview of Info.

The Chore Ideas tab ships pre-seeded with a starter set of common chores grouped by age band, so parents have somewhere to start before the library has been built up by real contributions from other families. Each seeded idea also carries a Suggested Age Group tag (2-3, 4-6, 7-11, 12+), so the tab can be browsed / filtered by age group as well as alphabetically. Each seeded idea includes a rough "feels like" time estimate, mapped to a suggested points value using the same logic as the Points suggestion in Chore Creation (points = ceil(minutes / 10), minimum 1 point) - shown as a preview next to the chore, and pre-filled into Points if a parent adds it as a chore for their own family (still fully editable, exactly as with any other chore).

The colour is applied to the schedule instance on the chore calendar.
The colour is based on the selected colour in the profiles by the parent for the child, or by the child.

The tab shuld have 2 sections for Chores and then for Freeze requests.
Chores section:
- This should have a list of all chores submitted by their children for validation.
- These should be all chores in an unverified status and should show information about the chore requiring verification
- Info in the list could be:
-- Chore Name

Clicking on the row should expand the info as a popup with the same details and the proof photo visible as a preview. This is the only window in which the photo is viewable - once the parent picks an outcome below, the photo is permanently deleted (see "Calm Chore Creation.txt").
The popup should also have 3 buttons in place of wordy text buttons: a custom face icon (drawn in the app's own line-art style, matching the mask figure and badges elsewhere) paired with a short always-visible label - happy face + "Completed", neutral face + "Partially Complete", sad face + "Incomplete". As the app is mobile-first, labels are always shown next to the icon rather than relying on hover.
Clicking these should change the status of the chore instance to Verified - Complete, Verified - Partially Complete , Incomplete.
Partially Complete should require input of "Awarded Points" i.e. of the total points, how many are awarded (defaulting to the points field for the chore).
Incomplete should require entry of reason for non-completion which should then be made visible to the child on their "My Chores" tab.

"Points Redemption" tab:
"Your child has been informed that Points earned from doing chores may be redeemed for treats during shopping, purchases, or simply screen time.
They have been asked to discuss this with you and ensure that points are redeemed regularly and with consistency. Points are only fun when they are used. Depending on what you child wants to use their points for, you will need to reduce / debit from their points total, with a number of points reduced being agreed upon by both of you based on the purpose of usage and the amount you spend."
This text, or a version of it can appear on this tab on the parent's login into the app.

This goes into a 'Requested Redemption' grid that shows redemption requests coming from the parent's children:
- Category (Grocery, Purchases, Eating Out, Screen time, Cash / Pocket Money, Other)
- Requested for (what they requested i.e., What would you like / Restaurant-cuisine / Screen time interval+Purpose of time / Amount)

This should have 2 buttons for the request: Approve / Reject.
Reject should require a Rejection reason and not debit any points.
Approve should approve the request and require entry of number of points to debit. When typing in points, the parents should also be able to see current point total of the child.
Doing so should debit the specified number of points from the points total of the child. They should not be allowed to debit more points than the child has and it may be a good idea for confirmation before debit to prevent mistaken debiting of wrong points.

Similar to the child's redemption feature, there needs to be multiple grids to show requests pending approval and those alreay approved / rejected.

"Chore Breaks" tab:
Parents can apply a break for chores by selecting a start and end date (>= start date validation) and selecting one or more or all of the children to who the break applies.
Depending on how it is applied, the Chore break should appear on the calendar of the affected child(ren).
Any existing choe instances for that period overlapping the break should get hidden cancelled. If the chore break itself is cancelled, then the instances need to restore and so it is probably necessary to have the instance status and any chore break status affect each other.
For the duration of the chore break, the child does not need to submit / perform any chores and the existing chore streak is "frozen" and remains in place untilthe next day without a chore break, when a chore can again be done. 
If the break is applied to a day for which a Chore Freeze was already used - whether auto-applied or an approved request - then the break overrides it and that freeze is restored to the child's weekly free-freeze count for it to be used again on a different day.


"Manage for [Child]" tab:
This tab only appears if the parent has at least one child profile set to Parent-Managed (see "Calm Chore Setup.txt"). It lets a parent track and operate chores on behalf of a child too young to have their own device / login.

If more than one child on the account is Parent-Managed, the tab starts with a child selector (e.g. a dropdown or a row of the children's nicknames / initials in their accent colour) so the parent can switch between which managed child they are acting on behalf of. The rest of the tab reflects whichever child is currently selected.

For the selected child, this tab mirrors the child login experience, but collapsed into parent-friendly single-step actions:
- Chore Calendar and chore list, same as the child would see, showing chores assigned to or open for that child.
- A "Mark Done" button per chore (in place of the child's Accept -> perform -> Submit for Verification flow). Tapping this still requires a live photo (from the parent's device) if the chore requires proof, and immediately asks the parent to rate the outcome using the same face-icon buttons used in Validate Chores (Completed / Partially Complete / Incomplete). There is no separate validation step, since the same parent would otherwise be both submitting and validating - points are credited and the streak updates immediately.
- Points, streak and tier are shown the same way as on the child's own Points tab, since the child cannot see this themselves.
- The parent can apply a Chore Freeze directly on the child's behalf (in place of the child requesting one), subject to the same free-freeze-per-week count that applies based on the child's current tier (see "Child Login Options.txt").
- Points redemption is a direct "Adjust Points" action the parent performs when they give the child a reward, rather than a request-then-approve flow, since there is no child-side request to respond to.
- Friends / leaderboard are not available for a Parent-Managed child in this version, since that assumes independent interaction the child isn't yet doing.
